1. はじめに

1.1. 導入（Getting Started）

本書の目的は、対話型定理証明支援系「Lean 4」を使用して数学を形式化する方法を学ぶことです。前提として、ある程度の数学的知識を仮定していますが、それほど高度なものは必要ありません。数論から測度論、解析学に至るまで幅広い例を取り上げますが、それらの分野の初歩的な側面に焦点を当てているため、もし馴染みのない内容であっても、学習を進めながら身につけていくことができるでしょう。また、形式手法に関する事前の知識も一切仮定していません。形式化とは、一種のプログラミングのようなものだと考えることができます。私たちは、Leanが理解できるような規則正しい言語（プログラミング言語のようなもの）で数学的な定義、定理、証明を記述します。その見返りとして、Leanはフィードバックや情報を提供し、式を解釈してそれが整形式（well-formed）であることを保証し、最終的に私たちの証明の正しさを保証してくれます。

Leanについての詳細は、LeanプロジェクトのページやLeanコミュニティのウェブページをご覧ください。本チュートリアルは、Leanの巨大かつ常に成長し続けているライブラリ「Mathlib」に基づいています。また、まだ参加していない方は、Lean Zulipオンラインチャットグループに参加することを強くお勧めします。そこには、質問に喜んで答え、精神的にサポートしてくれる、活気に満ちた温かいLean愛好家のコミュニティがあります。

本書のPDF版やHTML版をオンラインで読むことも可能ですが、VS Codeエディタ内からLeanを実行しながら、対話的に読み進めるように設計されています。始めるには：

  1. 以下のインストール手順に従って、Lean 4とVS Codeをインストールします。
  2. VS Codeの右上隅にある「forall（∀）」記号をクリックし、「Open Project」、「Download Project」、「Mathematics in Lean」の順に選択してリポジトリを取得します。
  3. 本書の各セクションには、例と演習問題を含む対応するLeanファイルが用意されています。これらは章ごとに整理された MIL フォルダ内にあります。そのフォルダのコピーを作成し、そのコピーの中で実験したり演習問題を解いたりすることを強くお勧めします。これにより元のファイルがそのまま保たれ、リポジトリが変更された際に行う更新も容易になります（下記参照）。コピーの名前は my_files など好きなものにして構いませんし、自分自身のLeanファイルを作成するためにも使用できます。

その上で、VS Codeのサイドパネルで教科書を開くには、次のように操作します：

  1. ctrl-shift-P （macOSの場合は command-shift-P）を押します。
  2. 表示されるバーに Lean 4: Docs: Show Documentation Resources と入力し、リターンキーを押します（メニュー内でハイライトされたらすぐにリターンキーを押して選択できます）。
  3. 開いたウィンドウで Mathematics in Lean をクリックします。

あるいは、Codespacesを使用して、クラウド上でLeanとVS Codeを実行することもできます。その方法についての詳細は、Github上の Mathematics in Lean プロジェクトページに記載されています。なお、前述したように、MIL フォルダのコピー内で作業することをお勧めします。

この教科書と関連リポジトリは現在も制作途中のものです。リポジトリを更新するには、mathematics_in_lean フォルダ内で git pull に続けて lake exe cache get と入力します（これは MIL フォルダの内容を変更していないことを前提としています。コピーの作成を勧めたのはそのためです）。

本書では、解説、指示、ヒントが含まれる教科書を読みながら、MIL フォルダ内の演習問題に取り組むことを想定しています。本文には、以下のような例が頻繁に登場します：

#eval "Hello, World!"

対応するLeanファイル内で該当箇所を見つけることができるはずです。その行をクリックすると、VS Codeの「Lean InfoView」ウィンドウにLeanからのフィードバックが表示され、カーソルを #eval コマンドの上に合わせると、ポップアップウィンドウにこのコマンドに対するLeanの応答が表示されます。ファイルを編集して、ご自身の例を試してみることをお勧めします。

さらに本書には、挑戦しがいのある演習問題がたくさん用意されています。これらを急いで飛ばしてしまわないようにしましょう！ Leanの本質は、ただ読むことではなく、対話的に数学を「実践する」ことにあります。演習問題を解き進めることは、その体験の中心となります。すべてを解く必要はありません。関連するスキルをマスターしたと感じたら、自由に先に進んで構いません。自分の解答は、各セクションに関連付けられた solutions フォルダ内の解答といつでも比較することができます。

1.2. 概要（Overview）

簡単に言えば、Leanは「依存型理論（dependent type theory）」として知られる形式言語で複雑な式を構築するためのツールです。

すべての式には型（type）があり、#check コマンドを使用することでそれを表示させることができます。一部の式は ℕ や ℕ → ℕ のような型を持ちます。これらは数学的対象です。

#check 2 + 2
def f (x : ℕ) := x + 3
#check f

一部の式は Prop 型を持ちます。これらは数学的命題です。

#check 2 + 2 = 4
def FermatLastTheorem := ∀ x y z n : ℕ, n > 2 ∧ x * y * z ≠ 0 → x ^ n + y ^ n ≠ z ^ n
#check FermatLastTheorem

一部の式は型 P を持ち、その P 自身が Prop 型を持ちます。そのような式は、命題 P の証明となります。

theorem easy : 2 + 2 = 4 := rfl
#check easy
theorem hard : FermatLastTheorem := sorry
#check hard

もしあなたが FermatLastTheorem 型の式を何とか構築し、Leanがそれをその型の項として受け入れたならば、それは非常に素晴らしい成果です（sorry を使うのはズルであり、Leanはそれを知っています）。これでゲームのルールは分かりました。あとはルールを学ぶだけです。

本書は、姉妹編のチュートリアルである『Theorem Proving in Lean』（Leanでの定理証明）を補完するものです。同書では、背後にある論理的枠組みやLeanのコアな構文について、より徹底的な入門を提供しています。『Theorem Proving in Lean』は、新しい食洗機を使う前に、取扱説明書を最初から最後まで読みたい人のためのものです。もしあなたが、とりあえず「スタート」ボタンを押して、ポットスクラバー機能の有効化はそのあとで考えたいタイプの人であれば、本書から始めて、必要に応じて『Theorem Proving in Lean』を参照する方が理にかなっているでしょう。

『Mathematics in Lean』が『Theorem Proving in Lean』と異なるもう一つの点は、本書ではタクティク（tactics）の使用に遥かに重点を置いていることです。複雑な式を構築しようとする際、Leanには2つのアプローチがあります。式そのものを書き下す（つまり、その適切なテキスト表現を記述する）か、あるいは式をどのように構築すべきかについての指示（instructions）をLeanに与えるかです。例えば、次の式は、「n が偶数ならば m * n も偶数である」という事実の証明を表しています：

example : ∀ m n : Nat, Even n → Even (m * n) := fun m n ⟨k, (hk : n = k + k)⟩ ↦
  have hmn : m * n = m * k + m * k := by rw [hk, mul_add]
  show ∃ l, m * n = l + l from ⟨_, hmn⟩

この証明項（proof term）は、1行に圧縮することができます：

example : ∀ m n : Nat, Even n → Even (m * n) :=
  fun m n ⟨k, hk⟩ ↦ ⟨m * k, by rw [hk, mul_add]⟩

一方、次のコードは同じ定理のタクティクスタイル（tactic-style）の証明です。-- で始まる行はコメントであるため、Leanからは無視されます：

example : ∀ m n : Nat, Even n → Even (m * n) := by
  -- m と n を自然数とし、n = 2 * k と仮定する。
  rintro m n ⟨k, hk⟩
  -- m * n が自然数の2倍であることを証明する必要がある。m * k の2倍であることを示そう。
  use m * k
  -- n を代入し、
  rw [hk]
  -- これで明らかになる。
  ring

VS Codeでこのような証明の各行を入力していくと、Leanは別のウィンドウに証明の状態（proof state）を表示し、すでに確立した事実と、定理を証明するために残っているタスクを教えてくれます。カーソルがある時点での証明の状態をLeanが常時表示してくれるため、行をステップ実行しながら証明を再現することができます。この例では、証明の最初の行が m と n を導入し（必要であればその時点で名前を変更することもできました）、さらに仮説 Even n を k と n = 2 * k という仮定に分解していることがわかります。2行目の use m * k は、m * n = 2 * (m * k) を示すことによって m * n が偶数であることを示すという宣言です。次の行では rw タクティクを使用してゴール内の n を 2 * k に置き換え（rw は "rewrite" の略）、最後の ring タクティクによって得られたゴール m * (2 * k) = 2 * (m * k) を解きます。

小さなステップとインクリメンタルなフィードバックを受け取りながら証明を構築できる能力は、非常に強力です。そのため、タクティクによる証明は、多くの場合、証明項を書くよりも簡単で迅速に行えます。両者の間に厳密な境界線があるわけではなく、上記の例の by rw [hk, mul_add] のように、証明項の中にタクティクを挿入することもできます。同様に、タクティク証明の途中に短い証明項を挿入することが役立つ場合も多々あります。とはいえ、本書ではタクティクの使用に重点を置きます。

上の例では、タクティク証明も1行にまとめることができます：

example : ∀ m n : Nat, Even n → Even (m * n) := by
  rintro m n ⟨k, hk⟩; use m * k; rw [hk]; ring

ここでは小さな証明ステップを実行するためにタクティクを使用しました。しかし、タクティクは高度な自動化を提供し、より長大な計算や大規模な推論ステップを正当化することもできます。例えば、パリティに関する命題を自動的に証明するための特定の規則を持ったLeanのシンプリファイア（simplifier）を呼び出すことができます。

example : ∀ m n : Nat, Even n → Even (m * n) := by
  intros; simp [*, parity_simps]

2つの導入部のもう一つの大きな違いは、『Theorem Proving in Lean』がコアとなるLeanと組み込みのタクティクのみに依存しているのに対し、『Mathematics in Lean』はLeanの強力かつ常に成長し続けているライブラリ「Mathlib」の上に構築されている点です。その結果、ライブラリに含まれる数学的対象や定理の使い方、そして非常に便利なタクティクのいくつかを紹介することができます。本書はライブラリの完全な概要として使用されることを意図したものではなく、詳細なドキュメントはコミュニティのウェブページに掲載されています。むしろ私たちの目的は、その形式化の根底にある思考様式を紹介し、ライブラリをブラウジングして自分で物事を見つけやすくなるように基本的なエントリーポイントを示すことです。

対話型定理証明はフラストレーションが溜まることもあり、学習曲線は急峻です。しかし、Leanコミュニティは新参者を非常に温かく迎え入れており、Lean Zulipチャットグループには質問に答えてくれる人々が24時間体制で待機しています。そこであなたにお会いできることを楽しみにしていますし、あなたもすぐにそのような質問に答えられるようになり、Mathlibの開発に貢献できるようになると確信しています。

それでは、受諾することを選んだ場合のあなたのミッションです：飛び込み、演習問題を解き、質問を抱えてZulipを訪れ、そして楽しんでください。ただし警告しておきます：対話型定理証明は、数学および数学的推論について全く新しい方法で考えるようあなたに挑戦してきます。あなたの人生は二度と元には戻らないかもしれません。
